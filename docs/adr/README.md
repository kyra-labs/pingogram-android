# Architecture decision records

One file per significant decision, `NNNN-title.md`, with Context · Decision · Consequences
(`docs/ARCHITECTURE.md`, Decision log).

| ADR | Decision |
|---|---|
| [0002](0002-open-source-licenses.md) | Open-source licenses screen: our own Gradle task lists each variant's dependencies and POM licenses at build time (not AboutLibraries, owner decision D17); our own Compose screens |
| [0003](0003-keep-connected-foreground-service.md) | "Keep connected" (foss only): a `specialUse` foreground service keeps TDLib's connection open while the user wants it; not `dataSync` (6 h/day on Android 15) nor `remoteMessaging` (cross-device relay) |
| [0004](0004-push-delivery.md) | Push delivery: Firebase Cloud Messaging through TDLib's `registerDevice` (encrypted) in the `gms` flavor only, after the owner uploads FCM credentials at my.telegram.org; `foss` stays Google-free (enforced by the build); UnifiedPush for `foss` is a follow-up |
| [0005](0005-passcode-lock.md) | Passcode lock: the platform's `BiometricPrompt` (Android 10+, strong biometrics, no `androidx.biometric`: it needs a `FragmentActivity` and brings AppCompat); PBKDF2-HMAC-SHA512 with 210,000 rounds; a growing wait after five wrong passcodes |
| [0006](0006-platform-location-manager.md) | Sharing the location: the platform's `LocationManager` (no Google Play services), continuous updates only while the sheet is open, foreground permissions only, coordinates and "Open in maps" instead of a map |
| [0007](0007-voice-recording.md) | Voice messages: the platform's `MediaRecorder`, Ogg Opus on Android 10+ and AAC (`.m4a`) on 8–9, no library; level and Telegram's 5-bit waveform from the recorder's peak amplitude |
| [0008](0008-lottie-for-animated-stickers.md) | Animated (TGS) stickers: Lottie for Android (pure Java, ~76 KB after R8, without its AppCompat dependency) behind `core:ui`'s `StickerAnimationDecoder`, not rlottie (native code built in CI); frames rendered off the main thread, first frames cached by sticker and size, at most 8 playing at 30 fps |
| [0009](0009-background-transfers.md) | Background transfers (FR-N4): the user's uploads and downloads (never automatic ones) keep the app running in WorkManager's `dataSync` foreground service, with a "Transfers" progress notification; promoted to a Live Update on Android 16 (`POST_PROMOTED_NOTIFICATIONS`) |
| [0010](0010-gpl-additional-permission-for-play-services.md) | License: GPL-3.0-or-later with an additional permission (§7) to combine Pingogram with Google's Play services and Firebase libraries, so `gms` builds can be distributed; not Apache-2.0, which would allow closed forks |
| [0011](0011-contacts-sync.md) | Contacts sync: opt-in (owner approval 2026-10-21), `READ_CONTACTS` its only use; names and numbers sent with `changeImportedContacts` only when turned on, on "Sync now" and when Contacts opens (once per process, 6 h apart), never in the background; turning it off sends `clearImportedContacts` |
| [0012](0012-camerax-and-zxing-qr-scanner.md) | QR code scanner: CameraX (`camera-compose`'s viewfinder, `ImageAnalysis`) and ZXing's decoder, on the device, in `:feature:scanner` only; not ML Kit or Play services' code scanner (`foss` stays Google-free); `CAMERA` only for the scanner, after a rationale; scan from an image through the Photo Picker; a code's text reaches TDLib only as a Telegram link |
| [0013](0013-deep-links.md) | Deep links: every Telegram link (`tg://`, `t.me`, `telegram.me`, `telegram.dog`) goes through TDLib's `getInternalLinkType` in one `LinkRepository`; browsable intent filters, `autoVerify="false"` (Telegram owns the domains; "Open Telegram links" in About on Android 12+), a `singleTask` activity, links kept through the login; login codes never acted upon, nothing joined or confirmed without the user; bot start links open the bot's chat with "Start" ready, never started by themselves |
| [0014](0014-direct-share.md) | Direct share: `SEND`/`SEND_MULTIPLE` filters on `MainActivity`, `content://` URIs read with their grant (never the app's own providers), waiting for the login and lock; the share sheet (forward sheet's picker) opens one chat with the share in its composer or sends to several after "Send"; copies held from `UploadCleaner` while they go to several chats; conversation shortcuts as Direct Share targets, the 8 most recent chats published |
| [0015](0015-call-media-engine.md) | The media engine for calls: NTgCalls (LGPL-3.0; protocol 8.0.0–13.0.0; TDLib's key through `skip_exchange`; NDK r28b, Oboe), as upstream builds it with video, from a pinned commit in `ntgcalls.yml`, fetched and verified like TDLib (`pingogram.ntgcalls`); not tgcalls, which has no Android build outside Telegram's own apps; APK budget raised to 50 MB `arm64-v8a` (owner, 2026-10-22) |
| [0016](0016-color-themes.md) | Color themes: the brand (Vibrant), 11 basic colors (Material 500 seeds, TonalSpot) and Monochrome, generated by `tools/theme` into Kotlin tables and splash resources (checked by CI), no runtime color library and no style choice; picked on Appearance → Theme with Pixel-style chips and a live preview; a basic color turns wallpaper colors off and is their fallback at medium and high contrast |
| [0017](0017-home-screen-widget.md) | Home screen widget of recent chats with Jetpack Glance, without a timer: redrawn when the chats change while the process runs and a widget is placed; nothing on the home screen behind a passcode. |
| [0018](0018-calls-and-telecom.md) | Calls in Android: Telecom through Jetpack's `core-telecom` as a self-managed calling app (an `AudioManager` fallback without Telecom), one call at a time; a `phoneCall`/`microphone` foreground service; call-style notifications, incoming in a new ringtone channel with a full-screen intent (heads-up when Android 14+ refuses it); the call screen as its own activity over the lock screen; a proximity wake lock at the earpiece |
| [0019](0019-video-and-group-calls-scope.md) | Video and group calls scope: all feasible with NTgCalls (frames as I420 into WebRTC's bundled `SurfaceViewRenderer`; group calls are NTgCalls' main use); 1:1 video next, then group voice chats, live streams after; until video ships, video calls ring and are answered as voice with a note on the call screen |
| [0020](0020-translations-on-weblate.md) | Translations on Hosted Weblate (owner, 2026-10-22): a component per module, pull requests from a `weblate` branch squashed into `chore(i18n): translations from Weblate`; a language ships at 80% translated, generated into the locale config and resource filters; `MissingTranslation` informational. |
| [0021](0021-chat-export.md) | Chat export (§5.9): a folder the user picks through the Storage Access Framework (no permission, no `androidx.documentfile`), HTML (self-contained, no script) or versioned JSON, optional media with a size limit; WorkManager's `dataSync` foreground service with a cancellable progress notification; the history paged newest first into temporary pages, written oldest first; secret chats and chats with protected content left out; a cancelled or failed export deletes what it wrote |
| [0022](0022-custom-emoji-rendering.md) | Custom emoji: pictures drawn over the fallback emoji from the cached text layout (a clip, no `InlineTextContent`, nothing composed or laid out again), TGS through `AnimatedStickers` sharing its frame cache and its 8 slots, WebP through Coil, WebM as their thumbnail; loaded by id for the messages on screen; no picker |
| [0023](0023-group-voice-chats-and-live-streams.md) | Voice chats and live streams on NTgCalls' group calls (no new native code) and TDLib's video chat functions, one call at a time with 1:1 calls (`CallLine`), joined muted as the chat's default participant; live streams received as one-second segments from `getGroupCallStreamSegment`; who is speaking from Telegram's recent speakers until audio levels are decided (open for the owner); group video, screen sharing, scheduling and invite links left out |
| [0024](0024-video-in-voice-chats.md) | Video in voice chats: the camera sent with NTgCalls' capture sources (its join payload always carries the camera's track) and `toggleGroupCallIsMyVideoEnabled`, where Telegram allows video; at most four others' videos received (`addIncomingVideo`), pinned first, then speakers; a grid of up to 2 × 2 tiles, a pin per device; no new library, permission or native code |
| [0025](0025-conference-calls.md) | Conference calls: TDLib has them (`createGroupCall`, `joinGroupCall` by link, the upgrade of a 1:1 call) but keeps their blockchain and encrypts frames on request (`encryptGroupCallData`), while NTgCalls runs its own chain. Pingogram patches NTgCalls (`tools/ntgcalls/`, built by its workflow): a conference mode without its chain whose encryptor calls TDLib for every frame (owner, 2026-10-24) |
| [0026](0026-screen-sharing.md) | Screen sharing (owner, 2026-10-24): `FOREGROUND_SERVICE_MEDIA_PROJECTION` and the call service's `mediaProjection` type only while the user shares, after Android's consent dialog (asked every time); NTgCalls' own capturer; in one-to-one calls the screen replaces the camera and the other side's screen shows fitted; voice chats share it as the presentation; a "You're sharing your screen" pill with Stop, and Stop in the notification |
| [0027](0027-proxies.md) | Proxies: SOCKS5, HTTP and MTProto through TDLib's own proxy functions, kept in TDLib's database (credentials never in Pingogram's settings, logs or saved state); Data and storage → Proxy lists, pings (only the user's proxies, when the page opens) and edits them; `tg://proxy` and `t.me/socks` links open a sheet that connects only on "Connect"; the wording of `REQUIREMENTS.md` §6.2 waits for the owner |
| [0028](0028-streaming-media.md) | Streaming videos (and later songs): a Media3 `DataSource` over TDLib's partial file, downloading from where the player reads at visible priority and stopped when it leaves; only videos that support streaming; the seek bar shows what is buffered |
| [0029](0029-locked-chats.md) | Locked chats (proposed, waiting for the owner): chosen chats behind the app's passcode, kept on this device only (Telegram has no API for it); open questions: whether locked chats hide from the lists or show as "Locked", whether their notifications are dropped or anonymous, and the widget, shortcuts and Direct Share |
